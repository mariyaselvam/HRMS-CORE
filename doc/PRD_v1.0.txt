1. Product Overview
1.1 Product Name
Working Name: PeopleOps HRMS

1.2 Product Description
PeopleOps HRMS is a cloud-based, multi-tenant HRMS SaaS platform designed for mid-sized tech and industrial companies with 100 to 1,000 employees. It centralizes employee management, attendance, payroll, leave, approvals, and reporting into a single, secure system delivered across three purpose-built application surfaces: a React Native mobile app for employees, an Angular + PrimeNG web dashboard for HR Admins and Managers, and an Angular + PrimeNG Super Admin Panel for platform operators. All three surfaces are powered by a single shared backend - Node.js/Express built in TypeScript with a PostgreSQL database.

1.3 Target Customers
• Tech companies (software, IT services, startups at scale)
• Industrial and manufacturing companies
• Operations-heavy organizations with shift-based or hybrid work environments

1.4 Target Users
• Company Admin / HR Head - full platform control within their tenant
• Managers / Team Leads - team visibility, approvals, and reporting
• Employees - self-service attendance, leave, and payslip access
• SaaS Super Admin - platform-level operations and client management

1.5 Business Goals
• Reduce HR operational overhead through automation
• Eliminate manual payroll and attendance errors
• Provide real-time workforce visibility to managers and HR
• Enable scalable HR operations as companies grow from 100 to 1,000+ employees
• Generate recurring SaaS revenue via per-employee monthly subscriptions



2. Problem Statement
2.1 Current Challenges
Companies with 100 to 1,000 employees typically face the following pain points:
• Attendance managed via Excel or fragmented, disconnected tools
• Payroll errors due to manual calculations and lack of cross-system data
• Poor visibility into employee time, leave consumption, and cost
• Complex approval chains that are entirely manual and untracked
• Compliance and audit risks from missing records and inconsistent data
• Disconnected employee experience with no self-service capability

2.2 Why Existing Solutions Fail
CategoryProblemEnterprise tools (SAP, Workday)Too complex, expensive, and slow to implement for mid-sized orgsSME tools (basic HR apps)Too basic, non-scalable, and weak on approval workflowsSpreadsheet-based systemsError-prone, no audit trail, no real-time accessFragmented point solutionsPoor integration, data silos, multiple logins for employees
2.3 Desired Outcome
A single, unified platform that automates HR operations, supports complex human workflows, scales without a system change, and is simultaneously easy for employees to use daily and powerful enough for HR teams to manage the full employee lifecycle.



3. Platform Architecture - Three Applications
PeopleOps HRMS is not a single application. It is composed of three distinct application surfaces, each purpose-built for a specific user group, all sharing a single Node.js/Express TypeScript backend and a PostgreSQL database, but maintaining separate UX, navigation, and access scope.

4.1 Recommended Project Structure
peopleops/                     # Nx monorepo root (or separate repos)
  apps/
    mobile/                  # React Native (TypeScript)
    admin-dashboard/         # Angular + PrimeNG
    super-admin/             # Angular + PrimeNG
    api/                     # Node.js Express (TypeScript)
  libs/
    shared-types/            # Shared DTOs, enums, interfaces
    shared-utils/            # Date utils, formatters, validators
  tools/                     # Build scripts, DB migration runners

Why a shared types library?
By placing all DTOs (e.g. CreateEmployeeDto, PayrollRecordResponse) in a shared-types lib, both the Angular frontends and the Express backend reference the same TypeScript interfaces. This eliminates an entire class of frontend/backend contract mismatches and makes refactoring safer.

6. User Journey (High-Level)
1. Company signs up for the platform (Super Admin activates tenant, assigns plan)
2. Company Admin completes org setup: departments, teams, locations, shifts, holidays
3. Employees are added via Admin Dashboard and invited to download the Mobile App
4. Employees begin marking daily attendance via the Mobile App
5. Managers handle leave and attendance approvals via the Admin Dashboard
6. HR Admin runs and finalizes monthly payroll in the Admin Dashboard
7. Payslips are automatically available to employees in the Mobile App
8. Company renews subscription; Super Admin monitors billing and platform health

9. Roles & Permissions (RBAC)
Access control is enforced at three levels: platform-level (Super Admin), company-level (roles within a tenant), and data-level (employees only see their own records).

RoleScopeAccess LevelSuper AdminPlatform-wide (all tenants)Full control of all tenants, plans, billing, and platform config via Super Admin Panel onlyCompany Admin / HR HeadSingle company tenantFull access to all HR modules, employee data, payroll, and company settings in Admin DashboardManager / Team LeadOwn team and direct reportsTeam attendance and leave approvals, read-only team analytics in Admin DashboardEmployeeOwn data onlySelf-service features in Mobile App: own attendance, own leave, own payslips, own documents
• Permissions are code-based (e.g. attendance:approve, payroll:run) and assigned to roles via the Admin Dashboard
• All roles and permissions are company-scoped - a user's role in Company A has zero access to Company B
• Super Admin access is completely isolated from tenant data and requires MFA
• All sensitive actions (payroll finalization, role changes, data deletion) are written to immutable audit logs

14. Assumptions & Constraints
14.1 Assumptions
• The client company is responsible for all employee salary disbursements - the platform produces payroll outputs only
• Internet connectivity is available for all users (offline mode is Phase 2)
• Legal and statutory compliance configuration (tax rules, provident fund, etc.) is initially handled manually by HR Admin; automated compliance is Phase 2
• Initial launch targets web (desktop browsers) for Admin Dashboard and Super Admin Panel (Angular + PrimeNG), and React Native (TypeScript) for the Mobile App (iOS and Android)
• SMS/email notifications are Phase 2; in-app push notifications are MVP

14.2 Constraints
• MVP does not include real-time biometric device integration
• No direct bank payment processing - the platform is not a payment service
• AI-powered analytics are explicitly out of MVP scope
• Mobile App will not support tablet or desktop form factors in MVP

14.3 Final Notes
This PRD is designed to be developer-ready, providing enough context for backend, frontend, and mobile engineers to begin architecture and sprint planning. It is intended to scale the platform from 100 to 1,000+ employees per company and grow into a full enterprise HRMS SaaS over multiple release phases.
